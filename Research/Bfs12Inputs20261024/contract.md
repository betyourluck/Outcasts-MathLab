## >>90 の項目をどう入れたか

1. **D(p) = 最初の成功頂点までの最短辺数**。根で成功すれば 0、根の素因数へ 1 回移って成功すれば 1。各頂点で許容 τ を尽くしてから次の頂点へ進む FIFO の BFS なので、
   最初の成功の深さは「失敗した源からだけ辺を張るグラフ」での最短距離になる（深さ k の頂点に初めて着いた時点で、深さ k 未満の頂点はすべての τ で失敗済み）。
2. **E₁: D(p) ≤ 1**。最初の成功が D ≥ 2 なら、その 1 入力で E₁ は棄却。そのときも Qleast-square は棄却されない。全 12 件で D ≤ 1 でも普遍的な主張にはしない。
3. **停止の 3 種類**: ① 実約数の証明書つき成功 / ② キューを完全に尽くした全失敗（到達集合 = 閉じた失敗集合 C）/ ③ 上限による未判定。最初の成功で止めるので、
   未訪問の部分に失敗閉集合がないとは言わない。
4. 手順の中身は >>86 §4 のまま: x の因数分解の全指数、法 p の非剰余素因数は**指数が偶数のものも含めて全部**、全許容 τ、全法 c での両枝判定。
5. 経路の記録: 各辺の親 (q, τ)、子 r、v_r(x)、最後の (c, x, d, y, z) と枝。
6. >>90 の Hensel の帰結は紙で追った（下の §Hensel）。数値の照合も入れる（判定ではなく G0 の assert）。
7. >>90 の「成功した候補数」は 2 通りに読めるので両方残す: BFS が止まるまでに調べた候補数と、根の全 τ のうち成功した源の数 S₀(p)（測定）。

## 記号

- p は 12 入力の素数（6 類 mod 840、p ≡ 1 mod 8 なので 2 は平方剰余）。χ(a) = (a∣p)（オイラー基準）。ℓ = ℓ(p) = 最小の素数非剰余。
- 頂点 q（法 p の非剰余素数）: σ(q) = 1（q ≡ 3 mod 4）/ 3（それ以外）、A_q = σ(q)·q。許容 τ = A_q τ² < 3p を満たす正の奇数（小さい順）。
- 源 (q, τ): c = A_q τ²、x = (p + c)/4（整数、0 < x < p、gcd(c, x) = 1 を assert）。
  **成功** ⇔ ある d ∣ x² が Type II: d ≡ −x、または Type I: d ≡ −px (mod c)。証明書は Type II が y = p(d+x)/c、z = p(x²/d + x)/c、
  Type I が y = (d + px)/c、z = (p²x²/d + px)/c で、4xyz = p(xy + xz + yz) を整数で確かめる。記録する d は Type II を先に、小さい順で最初のもの（>>86 の実装と同じ約束。成否には関係しない）。
- 辺: 失敗した源 (q, τ) から、x の素因数 r で χ(r) = −1 のもの全部へ。子は小さい順に、未発見ならキューの末尾に入れる。親は最初に見つけた源。
- **D(p)** = 最初に成功した源の頂点の深さ。**E₁** ⇔ D(p) ≤ 1。
- 測定用: Ch(p) = 根の失敗した源の非剰余素因数の集合（S₀ = 0 なら BFS の深さ 1 の頂点と一致）。頂点の状態 = τ を小さい順に最初の成功まで（成功 / 全失敗 / 未判定）。
  **E₁′(p)** = 根の失敗した源のうち、子に成功頂点を持つものの割合（源ごとの言い方で E₁ より強い。外れても E₁ は棄却されない）。

## 計算（各入力）

1. **BFS（判定に使う）**: 上の手順。各源で
   - 因数分解は √x までの試し割りと sympy `factorint` の 2 通りで一致させ、積が x に戻ることを確かめる。
   - 成功の判定は 2 経路: (i) d ∣ x² の全列挙、(ii) x² の約数の剰余集合を素因数冪ごとに法 c で掛け合わせて作る。両枝で一致を assert。
   - 成功なら証明書の恒等式 4xyz = p(xy + xz + yz) と y, z > 0 を assert。
   - 停止②なら、C のすべての頂点ですべての許容 τ が調べられて失敗していること、各 x の非剰余素因数がすべて C に入っていることを assert する。
2. **掃き出し（測定）**: 根の全 τ を両枝で判定して S₀(p) と成功した τ を記録。根の失敗した源の子 Ch(p) すべての状態を求め、E₁′(p) と「掃き出しから見た E₁」を出す。
   BFS と掃き出しの両方が判定できた入力では、S₀ > 0 ⇔ D = 0、S₀ = 0 のとき「D = 1 ⇔ Ch(p) に成功頂点がある」を assert する（判定関数は共通で、照合するのは走査の論理）。
3. **Hensel の数値照合（G0）**: 調べた各頂点 q と、そこで調べた x を割る奇素数 r のうち k_ref ≥ 2 のものについて、全許容 τ で v_max = max v_r(x(τ)) を総当たりし、
   v_max ≥ k_ref ≥ k₉₀ を assert する。k₉₀ = max{k : A r^{2k} ≤ 3p}（>>90 の条件）、k_ref = max{k : A(r^k − 2)² < 3p}（下の改良）。

## Hensel（>>90 の導出の紙の監査、計算前に済み）

>>90 の主張「A r^{2k} ≤ 3p ⇒ 許容される奇数 τ で r^k ∣ x(τ) となるものがある」を追った。r ∣ x(τ₀) で r が A や τ₀ を割ると r ∣ p となって 0 < x < p に反するので
gcd(r, Aτ₀p) = 1、f(T) = p + AT² の単根 τ₀ は法 r^k の根 b に一意に持ち上がり、f(0) = p なので b ≢ 0、f は偶関数なので r^k − b も根、r^k は奇数なので片方が奇数。
その奇数を τ にすると τ < r^k、Aτ² < A r^{2k} ≤ 3p、gcd(4, r) = 1 から r^k ∣ x(τ)。正しい。

小さな改良: その奇数の根は 1 ≤ τ ≤ r^k − 1 で、r^k − 1 は偶数なので **τ ≤ r^k − 2**。したがって **A(r^k − 2)² < 3p で十分**（>>90 の条件はこれを含む）。
2521、A = 11、r = 3 では、k = 3 で 11·25² = 6875 < 3p = 7563 < 8019 = 11·3⁶ なので、3³ は改良した条件で保証され（τ = 25、>>88 の表の法 27 の根 {2, 25}）、>>90 の条件では保証されない。
3⁴ はどちらの条件でも保証されないが τ = 25 で実現する（>>90 の例のとおり）。既知の Hensel の補題からの直接の帰結で、新しい定理とは数えない。
>>90 が書くとおり、保証できるのは同じ頂点の平方源に含まれる実指数までで、余因子・次の頂点・移動先の全法での成功は保証しない。

## 止める条件（G0）と上限

- 入力のリスト、HEAD、追跡と差分の確認のどれかが違う → 計算の前に止める。
- 因数分解の 2 通りの不一致、成功判定の 2 経路の不一致、証明書の恒等式の失敗、② の閉包の検査の失敗、BFS と掃き出しの不一致、Hensel の v_max < k_ref
  → その入力で止め、ログを残す。判定は書かない。スクリプトの不具合なら新しいコミットで直し、直した内容を README に書いてから全入力をやり直す（failures #20 の型）。
- 上限: 入力ごと・走査ごと（BFS / 掃き出し）に 500,000 源または 1,800 秒、プロセス全体で 4 時間。超えたらその走査は ③。
  見積もり: 自己検査の 1 源 0.2 ミリ秒から、D ≤ 1 なら全体で数分。D ≥ 2 の入力は深さ 2 まで広がるが、上限内に収まる見込み。
- 入力・順序・上限・見立ては、この契約の push の後は変えない。
